## 2. 규칙 명세 (동결 · 그대로 옮긴다)

소스: `backend/scripts/binance/kinematics_paper.py` — 이 파일이 페이퍼와 실거래를
**같이** 돌린다. `--live` 만 붙이면 주문 경로가 열린다. 규칙 코드는 하나다.

### 2.1 기질

```
1분봉      runs/bars1m/<SYM>/<날짜>.parquet  (틱 수집기가 접어 둔 것)
유니버스   configs/binance_collect_universe.txt  (521종목)
후행 요구  **790분** = WIN_H 60 + WINDOW 360 + 2×DELTA 360 + 10
           ⚠ 신규 상장은 13시간 넘게 신호가 안 난다. 정상이다.
```

### 2.2 신호 — 위약 승률의 **속도**

```python
WIN_H, WINDOW, DELTA = 60, 360, 180          # 동결
fw   = c[t+60]/c[t] - 1                      # 60분 앞 수익
win  = (fw > 0)                              # 이겼나
rate = win.rolling(360, min_periods=180).mean().shift(60)   # ⚠ shift 필수(미래참조 방지)
vel  = rate - rate.shift(180)
acc  = vel  - vel.shift(180)
neff = 360/60 = 6
se   = sqrt(p(1-p)/neff),  p = rate.clip(0.01, 0.99)
z_vel = vel / (se * sqrt(2))
z_acc = acc / (se * 2)
```

`rate` 는 "최근 6시간 동안 60분 뒤에 올랐을 확률". `z_vel` 은 그 확률이
**얼마나 빨리 변하고 있는가**. 값이 음수일수록 최근에 많이 진 종목이다.

### 2.3 생존 필터

```
직전 60분 분당 체결 수 중앙값 >= 5      (MIN_LIVE_TR = 5.0)
```

### 2.4 밴드 — 롱과 숏이 **거울**이다

```
롱   -1.25 <= z_vel <= -0.25   그리고  z_acc <  +0.5
숏   +0.25 <= z_vel <= +1.25   그리고  z_acc >  -0.5
```

⚠ **상한(-0.25)이 핵심이다.** 상한 없이 돌린 초판이 -18.8%였다. 밴드 밖은
후보가 아니다 — 신호가 없으면 그 앵커는 그냥 넘어간다.

### 2.5 선별 — 부호를 틀리면 정반대가 된다

```
롱 후보  z_vel **낮은 순**  (밴드 아래끝에서 가까운 쪽부터)
숏 후보  z_vel **높은 순**  (밴드 위끝에서 가까운 쪽부터)
```

### 2.6 슬롯 — 롱·숏을 **따로** 채운다

```
슬롯 6 = 롱 3 + 숏 3        half = slots // 2
같은 종목 중복 금지
한쪽만 채우면 시장 중립이 깨진다 — 코드가 각 반쪽을 독립으로 채운다
빈 자리는 다음 앵커에 다시 채운다 (슬롯 재충전)
```

### 2.7 진입 · 청산

```
앵커      벽시계 **5분 격자** (STEP = 5)
진입      그 앵커의 1분봉 종가
청산      진입 + **240분** (--hold-min 240)
익절      없음
```

### 2.8 손절 5% — 만기보다 **먼저** 본다

```
롱  최근 구간 1분봉 **저가** <= entry_px * 0.95  →  -5.00% 로 청산
숏  최근 구간 1분봉 **고가** >= entry_px * 1.05  →  -5.00% 로 청산
```

⚠ 페이퍼는 손절가 정확히 체결로 본다(지정가 가정). 갭이 나면 실제는 더 나쁘다.
⚠ **실거래에서는 거래소가 판정한다.** 걸어 둔 STOP 이 트리거되면 포지션이 사라져
있고, 엔진은 그것을 "청산됨"으로 읽어야 원장이 맞는다.

### 2.9 손익 규약

```
롱  net = (exit/entry - 1)*100 - 0.072 - funding
숏  net = **(entry-exit)/entry***100 - 0.072 - funding     ← 교훈#89
수수료 0.072% = 편도 0.036% × 왕복 (페이퍼 가정)
```

⚠ **실거래 실측은 왕복 0.1003%** 다(계좌 15 · 48거래 실측). 거래당 **-0.0283%p**
가 페이퍼보다 더 빠진다. 하루 37건 × 지분 1/6 → **자본 일수익 -0.175%p/일**.
페이퍼 +1.42%/일이 실거래에서는 **약 +1.25%/일**이 기대치다.

## 6. 남는 위험 — 정직하게

### 6.1 상위 3건이 총기여의 **142%** 다

```
총기여 0.1037 (자본 +10.37%)
상위 3건 합 0.1475 (142%)
최고건 BTRUSDT 숏 **+58.21%** — 2026-09-01 07:15 UTC, 가동 **첫날**
```

**상위 3건을 빼면 이 갈래는 적자다.** 그리고 최대 건이 첫날에 나왔다. 7일이라는
표본에서 이런 구조는 "전략이 좋다"와 "운이 좋았다"를 구분하지 못한다.

### 6.2 숏 다리가 특히 그렇다

```
숏 140건  거래당 +0.223%  상5제외 **-0.555%**  승률 **45.7%**
롱 136건  거래당 +0.234%  상5제외  -0.038%     승률  54.4%
```

숏은 **승률이 절반 아래인데 거래당이 양수**다. 전형적인 꼬리 의존이다. 롱 다리만
떼어 내는 구성(`3 --long`)도 검토 가치가 있으나, **그건 이 문서의 범위 밖이다** —
바꾸려면 페이퍼에서 새 갈래로 갈라 재라.

### 6.3 아카이브 뒷받침이 없다

1.2에 적은 그대로다. 오늘 imp 축이 무너진 방식(신호 불일치 · 미래보기)을 겪은
뒤라, **`kine` 축도 같은 검사를 받아야 한다**. 고쳐 둔 `imp_axes` 를
`--signal kine` 으로 돌리는 것이 다음 과제다.

### 6.4 실거래 수수료가 엣지의 12%를 먹는다

```
페이퍼 가정 0.072%  ·  실거래 실측 0.1003%  →  거래당 -0.0283%p
하루 37건 × 지분 1/6  →  자본 **-0.175%p/일**
페이퍼 +1.42%/일  →  실거래 기대 **약 +1.25%/일**
```

빈도가 높은 전략이라 수수료가 그만큼 크게 들어온다. 등급이 내려가면(거래량 감소)
더 나빠진다.

### 6.5 시장 중립이 아니다

"롱숏"이지만 **금액 중립일 뿐 베타 중립이 아니다**. 롱 3종목과 숏 3종목의 베타가
다르면 시장 방향에 노출된다. 실제로 2026-09-08 유니버스가 전 구간 양수였던
구간(18:45)에 이 갈래는 −0.69%/일이었다.
